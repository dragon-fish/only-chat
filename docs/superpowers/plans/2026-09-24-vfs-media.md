# 投影挂载、读图与改图 实现计划（计划 2/2）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Agent 能看到本对话里生成和上传的图片（`/artifacts`、`/uploads` + `read_file`），并能用 `generate_image` 的 `reference_images` 改图。

**Architecture:** 投影挂载是 workspace files service 上的只读视图：条目由 `artifacts`/`artifact_runs`/`messages` 在读取时派生。`read_file` 读图时工具输出用保留键 `__attachments` 交出 attachment id，累加器移到 `tool_result.attachments`；模型侧在 tool 消息后紧跟一条带图的 user 消息（本轮由 `prepareStep` 追加，重建由 `buildModelMessages` 产出，二者一致）。

**Tech Stack:** TypeScript, cordis, D1/drizzle, AI SDK v6, Vue 3 + Pug, Vitest。

**Spec:** [docs/superpowers/specs/2026-09-23-background-tasks-design.md](../specs/2026-09-23-background-tasks-design.md) §3.2、§4

## Global Constraints

- 挂载：`/artifacts/<artifact_id>.<ext>`（run 输出）、`/artifacts/msg-<attachment_id>.<ext>`（聊天模型直接生成）、`/uploads/<attachment_id>.<ext>`；扩展名 png/jpg/webp/gif 由 MIME 决定。
- 投影挂载只读：写入、编辑、重命名、删除、恢复返回新错误码 `READ_ONLY`。
- 路径标注仅在本轮工具含 `read_file` 或 `generate_image` 时加入；格式见 spec §4.0。
- 工具结果中的图片只在模型输入模态含 `image` 时交付；否则返回陈述，不是错误。
- `__attachments` 是保留键，只有累加器读取，绝不写进持久化的 `content`。

## Review Focus

1. **读别人的图**：路径里的 id 属于别的用户或别的对话 → `FILE_NOT_FOUND`，不能泄露存在性。（Task 1 测试）
2. **已删除的 artifact**：`deleted_at` 非空的不出现在列表、不可读。（Task 1 测试）
3. **重建与本轮一致**：同一条 assistant 消息，本轮追加的 user 图片消息与下一轮 `buildModelMessages` 重建的完全相同（前缀缓存）。（Task 2 测试）
4. **模型不支持看图**：`read_file` 读图返回陈述且不附图；`generate_image` 带参考图但生图模型不支持图片输入 → 错误，不建 run。（Task 3、4 测试）
5. **Anthropic 角色交替**：tool 结果 + user 图片被 SDK 合并为同一条 user 消息，工具结果块在前。（Task 2 测试）
