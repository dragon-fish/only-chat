# 聊天页外壳重做设计

## 1. 背景与目标

MVP 的聊天页是毛坯：底栏用三个并排的重控件（带边框的文字按钮、带边框的下拉框、一张三行高的卡片）解决一件事，全局顶栏只承载应用名和一个连接状态点。实际使用时底栏看起来像散架的浮层。

本轮不发明设计，直接照抄已被验证的参考：**Cherry Studio 2.0**（整体布局、顶栏 chip、Composer 整卡、思考强度弹层）与 **Codex**（滑块本体）。我们没有 UI 设计师，抄成熟设计是最快且风险最低的路径。

目标：

- 顶栏承载真实信息，而不是占着高度显示一个应用名。
- Composer 成为一个视觉整体，控件语言统一。
- 思考强度可发现、可精确调节、不易误触。

## 2. 范围

### 包含

- app-shell 顶栏改为插槽，由各路由填充；应用名与连接状态移入侧栏顶部。
- 聊天页自己的顶栏内容：项目/会话标识、模型 chip、会话设置入口、移动端抽屉按钮。
- Composer 收成一张整卡：输入框与底部工具行共用边框。
- 思考强度控件重做：底栏 chip + 弹层（Codex 式宽滑块）。
- 聊天页与设置页的图标语言统一。

### 不包含

- **模型选择器内部**的搜索、能力标签筛选、分组与徽章。chip 点开后沿用现有 `ModelPicker`，其重做属于后续一轮。
- 供应商设置页重做。
- 供应商多端点 / 模型携带协议与用途的数据模型改造。
- 侧栏下钻式导航。
- models.dev 能力自动填充。
- 消息气泡、思考过程折叠、空状态的视觉重做。

## 3. 顶栏

### 3.1 问题

现状 `app-shell.vue` 有一条 `h-12` 的全局 header，内容是 `only-chat` 加一个连接状态圆点，外加移动端的抽屉按钮。信息量不足以占据一条常驻横栏。

### 3.2 方案

保留这一行，但改为**插槽**，由每个路由填充自身的标识与操作。问题不在于"有一条栏"，而在于"栏里没有信息"。

- 应用名与连接状态点移入**侧栏顶部**，与已有的设置按钮同一行。
- 移动端抽屉按钮（`md:hidden`）留在顶栏最左，因此每个路由都有稳定的侧栏入口。设置页的标题写在滚动正文里，会随内容滚走，不能承担这个职责。

聊天页填充：

```
[☰ 移动端] [项目名 ›] [◆ 模型名 ⌄]  ⋯⋯  [⚙ 会话设置]
```

- 项目名仅在会话属于某个 Project 时显示，其后跟一个分隔符。它是**只读标签，不是控件**——由项目名进入项目设置属于后续的侧栏下钻一轮。
- 模型 chip 显示生效模型，点击打开现有的 `ModelPicker`。
- 会话设置沿用现有弹层。

设置页填充：`[☰ 移动端] [页面标题]`。

### 3.3 明确不做

不实现"内容位于顶部时顶栏透明、滚动后实体化"的变形效果。那是 iOS 液态玻璃的设计语言，与本项目其余部分不一致，且需要额外的滚动观测与内容留白。**顶栏始终是常规顶栏。**

## 4. Composer

一张 `rounded-xl` 边框卡片，内部自上而下为附件预览、输入框、工具行。输入框自身不再带边框。

- 输入框高度自适应内容：初始约三行，随输入增长，达到上限后在输入框内部滚动，卡片本身不再长高。上限取视口高度的一个固定比例，具体数值由实现选定并在两个视口人工确认。
- placeholder 缩短为一句，不再把三条快捷键说明塞进占位符。
- 输入框在移动端字号必须为 **16px**。iOS Safari 会对字号小于 16px 的聚焦输入框强制缩放，体验极差；桌面端仍用 14px。
- 工具行左侧：附件按钮。右侧：思考强度 chip、发送按钮。
- 发送改为圆形图标按钮；生成中替换为停止按钮，位置不变。
- 所有工具按钮统一为等尺寸的无边框幽灵按钮，不使用带边框的文字按钮或带边框的下拉框。

本节的卡片、边框、聚焦环、附件预览与上述字号规则均由 shadcn-vue 的 `input-group` 与 `attachment` 组件提供，不自行实现。

不引入 token 统计与速率读数：目前没有可靠的数据来源，属于范围外。

## 5. 思考强度

### 5.1 底栏 chip

显示当前生效档位（例如 `中`），点击打开弹层。

chip 在两种情况下禁用，并通过 `title` 分别说明原因，而不是静默消失——一个消失的控件无法解释自己为何消失：

- 尚未选定生效模型（新会话且无任何默认模型）：提示先选择模型。
- 已选定模型但其未声明 `reasoning` 能力：提示该模型不支持推理。

### 5.2 弹层

三个非强度状态（关闭 / 自动 / 具体强度）由三个语义单纯的控件分别承载，而不是全部压进一条滑块：

```
思考   [开 ●───]                              默认
──────────────────────────────────────────────────
[自动]   极低    低     中     高    超高   Max   Ultra
          ●──────●─────◉──────●─────●─────●─────●
```

- **标题行**：左侧 `思考` 加总开关，右侧一个 `默认` 按钮——仅在当前为显式覆盖时出现，点击写回继承。
- **滑块行**：行首一个 `自动` 开关，其后是强度滑块。

**不采用** Cherry Studio 2.0 的 `更快` / `更智能` 端点标注：那两个词只描述方向，不告诉用户当前处在哪一档，也无法表达"自动"。改为直接显示档位名。

### 5.3 滑块只承载强度

滑块是一条**单调强度轴**，档位自弱至强：

```
极低 · 低 · 中 · 高 · 超高 · Max · Ultra
```

`关闭` 和 `自动` 都**不在**轴上，因为它们不是强度。把 `自动` 放在轴的最左端会宣称"自动比极低还弱"，而自动实际可能落在任何一档——这与 `关闭` 是同一类语义错误，处理方式也相同：摘出去交给开关。

外观照抄 Codex：

- 离散刻度，每个可用档位一个刻度点。
- 大号白色圆形滑块，**可按住左右拖动**，松手吸附到最近刻度；同时保留点击刻度直接跳转。
- 轨道已填充部分随档位升高加深颜色。
- 控件整体偏宽，触摸目标显著大于刻度点本身。移动端与桌面端使用同一控件，不降级为选项列表——宽滑块的误触率低于密集排列的列表行。

**每一档都要有可读的名字**，不能只靠位置表达：当前档位名显示在滑块上方，其余档位通过刻度标签或悬停提示可辨认。具体呈现方式由实现在两个视口人工确认后选定，但"用户必须能知道自己选中的是哪一档"是硬要求。

### 5.4 三个控件的联动

- `思考` 关闭 → `自动` 开关与滑块**同时置灰**。
- `自动` 打开 → 滑块置灰，且不显示选中态（此时没有"当前档位"可言）。
- 点击滑块任意刻度 → `自动` 自动关闭，并选中该档。
- 重新打开 `自动` → 释放已选强度，回到由供应商决定。

### 5.5 控件来源

沿用 `reasoningStopsFor(capabilities, protocol)` 作为唯一来源，不改变其语义。组件把它的返回值拆成三部分：

- 返回值中是否含 `off` → 决定**总开关是否可用**。模型未声明 `reasoning_can_disable`、或协议本身无法表达关闭时，总开关禁用并锁在"开"，并说明原因——不假装能关。
- 返回值中是否含 `auto` → 决定 **`自动` 开关是否可用**。推理模型恒为可用。
- 其余档位 → **滑块刻度**。未声明 `reasoning_efforts` 表示**不限制**，所有强度可选。

任何档位都不从模型 id 推断。

### 5.6 三态与存储

存储层的三态是：**继承**（不写任何键）、**显式开**（含具体强度或自动）、**显式关**。

三个控件显示的始终是**生效值**；一旦为显式覆盖，`默认` 按钮出现，点击恢复继承。这与 Project 设置页既有的"继承自 Project / 会话覆盖 + 恢复"一致。

写入沿用既有的 `choiceToParams`，两个独立存储键的映射不变：

| 控件状态 | 写入 |
|---|---|
| 继承 | 一个键都不写 |
| 思考关 | `{ reasoning_enabled: false }` |
| 思考开 + 自动开 | `{ reasoning_enabled: true, reasoning_effort: null }` |
| 思考开 + 自动关 + 档位 X | `{ reasoning_enabled: true, reasoning_effort: X }` |

## 6. 错误与边界

- 未连接时发送禁用并给出提示，沿用现状。
- 模型不支持推理、或协议无法表达关闭时，对应控件禁用并说明原因，不假装可用。
- 弹层受视口高度约束并在内部滚动，遵循既有滚动归属规则：每个定高区域只有一个纵向滚动所有者。
- 顶栏与 Composer 均为固定高度区域，不参与滚动。

## 7. 测试与验收

- 纯函数（档位推导、三态映射）继续由单元测试覆盖。
- 组件本身在本仓库**无法自动化测试**：单元测试项目为 node 环境，未装 Vue 插件、jsdom 与测试工具。因此：
  - `pnpm typecheck` 与 `pnpm build` 只能证明模板可编译，**不能证明渲染正确**。本轮之前已有两次编译通过但运行时损坏的先例。
  - **合并前必须在真实浏览器中人工查看成品。** 本次重做的起因正是"评审确认渲染符合代码"但从未有人实际看过它。
  - 验证走**本地 dev server**，**不要推分支触发预览部署**：预览部署与生产共用 `wrangler.jsonc` 里的同一套绑定（同一个 D1、同一个 R2），没有独立的预发数据库，因此任何在预览站上的操作都会往生产库写脏数据。
- 桌面与移动两个视口的人工验收由人执行，不得由自动化流程声称完成。

## 8. 参考来源

- Cherry Studio 2.0：顶栏 chip 布局、Composer 整卡、思考强度弹层的整体结构（当前值 + `默认` 恢复按钮）。其 `更快/更智能` 端点标注不采纳，改为直接显示档位名。
- Codex：滑块本体（离散刻度、大白圆点、可拖拽、颜色随档位加深）。
- Claude 移动端：确认"低信息量元素不值得常驻横栏"，但其悬浮圆钮与滚动变形不采纳。
